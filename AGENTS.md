# APEX / GABBY ENGINEERING AGENT LAW

This repository is an APEX/Gabby implementation surface. The canonical visual contract lives in `rahmaanherman-source/Apex-Hub` and must be treated as engineering law.

## Mandatory UI rules

- Inspect the existing implementation before creating replacements.
- Never crop, shorten, delete, or hide primary content merely to fit a viewport.
- Preserve complete horizontal collections. If content extends beyond the viewport, users must be able to scroll/swipe left and right to reach it.
- Preserve vertical overflow with usable scrolling.
- Provide a discoverable `WHOLE PICTURE` / `OVERVIEW` path so the user can see the complete workspace and jump to each region.
- Responsive behavior may reflow or collapse panels, but must not destructively remove primary content.
- Maintain exactly ONE Gabby runtime, conversation, voice, command system, and canonical orb.
- Gabby must not obstruct primary work.
- Preserve existing working functionality during UI upgrades.
- Do not replace a complete composition with a simplified approximation merely because it is easier to implement.

## Verification law

A code edit, screenshot, preview, or AI statement is not proof of completion.

Required loop:

`INSPECT → CHANGE → BUILD → TEST → RUN → INTERACT → VISUAL-CHECK → EVIDENCE → REPORT`

Publish is successful only after the real deployed runtime can be opened and exercised.

If implementation differs from the canonical APEX/Gabby visual reference, fix it or explicitly document an authorized deviation. Never silently simplify.
