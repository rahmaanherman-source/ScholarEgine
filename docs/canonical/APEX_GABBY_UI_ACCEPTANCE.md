# APEX / GABBY UI ACCEPTANCE CHECKLIST

Use this checklist for every UI upgrade touching the workspace.

- [ ] All primary content remains present.
- [ ] No destructive cropping or shortening is used to fit the viewport.
- [ ] Wide collections can be scrolled/swiped left and right.
- [ ] Tall content can be scrolled vertically.
- [ ] `WHOLE PICTURE` / `OVERVIEW` is discoverable and shows the complete workspace.
- [ ] Every primary region is reachable from the overview.
- [ ] Exactly one Gabby runtime is present.
- [ ] Exactly one canonical Gabby orb is present.
- [ ] The orb does not obstruct primary work.
- [ ] Existing working capabilities remain functional.
- [ ] Source code was inspected before modification.
- [ ] Build passes.
- [ ] Tests pass.
- [ ] Runtime was actually opened.
- [ ] Horizontal/vertical navigation was exercised.
- [ ] Visual behavior was checked against the canonical reference.
- [ ] Evidence was recorded before reporting success.

## Required status vocabulary

Use `EXISTING`, `MODIFIED`, `NEW`, `MISSING`, `DUPLICATE`, or `UNVERIFIED` when reporting implementation state.

Do not use `COMPLETE`, `FIXED`, `LIVE`, or `VERIFIED` without the corresponding execution evidence.
